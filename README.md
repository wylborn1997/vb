# 粉丝应援助手 · 产品说明（MVP）

> 面向**小范围粉丝群**的微博互动辅助微信小程序。  
> 目标：缩短「明星发博 → 评论应援 → 控评捞评」的操作路径，不追求商业级实时性与全自动化。

---

## 一、产品定位

| 项 | 说明 |
|---|---|
| 使用场景 | 粉丝群（几十～几百人），跟进 1～5 位明星 |
| 核心用户 | 需要快速评论、参与控评的普通粉丝 |
| 非目标 | 大规模舆情监控、全自动批量点赞、对外商业化运营 |

---

## 二、MVP 功能范围

### ✅ v1 必做（可交付）

#### 1. 明星发博提醒

- 管理员配置关注明星列表（微博 `user_id`、昵称、头像）
- 后端定时检测目标账号是否有**新微博**（轮询间隔建议 3～5 分钟）
- 发现新博后，向已订阅用户发送**微信订阅消息**
- 通知内容：明星昵称、微博摘要、发布时间
- 点击通知进入**微博详情页**，可查看正文、配图，并快捷发评论

**体验预期：** 有延迟（分钟级），不保证秒级；足够粉丝群日常使用。

#### 2. 绑定微博 + 预设文案评论

- 用户通过 **OAuth 2.0** 绑定自己的微博账号（不在小程序内存储密码/Cookie）
- 支持多套**评论模板**（如控评、彩虹屁、数据帖），可按明星/场景分类
- 发评论前可**预览、编辑**模板内容
- 一键提交评论（后端代调微博 `comments/create`）
- 显示发送结果：成功 / 失败 / 频控提示

#### 3. 控评助手（查评 + 跳转）

- 输入目标微博链接或从「最新提醒」进入
- 按**评论时间顺序**分页加载评论列表
- 支持按**关键词**过滤（如应援口号、指定话题）
- 支持识别含**图片/表情**的评论（以 API 返回字段为准）
- 每条评论提供：**复制链接**、**打开微博**（引导至 App/H5 手动点赞）

> v1 不做小程序内自动点赞；点赞动作由用户在微博 App 内完成。

---

### ⏳ v2 可选（后续迭代）

- 应援任务协作（团长发布任务、成员认领）
- 评论发送队列（间隔发送，降低频控风险）
- 热评点赞数变化提醒
- 多账号切换（小号应援）
- 接入微博商业订阅 API（更低延迟、更稳定）

---

### ❌ 明确不做

- 存储用户微博密码或 Cookie
- 小程序内自动点赞、自动转发
- 监测全网任意账号的秒级推送
- 大规模爬虫、高并发控评

---

## 三、用户流程

### 3.1 首次使用

```
打开小程序 → 微信登录 → 订阅消息授权 → 绑定微博（OAuth） → 选择关注的明星 → 完成
```

### 3.2 明星发博

```
后端发现新博 → 推送订阅消息 → 用户点击 → 微博详情页 → 选模板 / 编辑 → 发送评论
```

### 3.3 控评捞评

```
进入控评页 → 粘贴微博链接 → 加载评论 → 输入关键词过滤 → 复制链接 / 打开微博 → 手动点赞
```

## 四、技术方案

### 4.1 技术栈

| 层级 | 选型 |
|------|------|
| 前端 | uni-app（编译为微信小程序） |
| 样式 | Tailwind CSS（需使用 uni-app 兼容方案，如 uni-app x 或 postcss 适配） |
| 后端 | Node.js / Python（二选一，负责 OAuth、API 代理、监测任务） |
| 数据库 | SQLite / MySQL（用户、模板、明星配置、发博记录） |
| 通知 | 微信订阅消息 |

### 4.2 系统架构

```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│  微信小程序      │────▶│  自建后端 API    │────▶│  微博开放平台    │
│  (uni-app)      │◀────│  (OAuth/代理)   │◀────│  (comments 等)  │
└─────────────────┘     └────────┬────────┘     └─────────────────┘
                                   │
                    ┌──────────────┼──────────────┐
                    ▼              ▼              ▼
              ┌──────────┐  ┌──────────┐  ┌──────────────┐
              │  数据库   │  │ 定时任务  │  │ 微信订阅消息  │
              └──────────┘  │ 发博监测  │  └──────────────┘
                            └──────────┘
                                   │
                            ┌──────┴──────┐
                            │ 监测数据源   │
                            │ 官方 API 或  │
                            │ 轻量爬虫*   │
                            └─────────────┘
                            * 小范围自用，需专用微博账号 Cookie，约 3 个月更新
```

### 4.3 微博能力对接

| 能力 | 实现方式 | 备注 |
|------|----------|------|
| 用户绑定 | OAuth 2.0 + web-view 授权页 | token 存后端，约 30 天需重新绑定 |
| 发评论 | `comments/create` | 需用户授权，注意频控 |
| 读评论 | `comments/show` 分页 | 本地做关键词过滤 |
| 监测发博 | 定时拉取 `user_timeline` 或轻量爬虫 | 小范围群可接受 3～5 分钟延迟 |
| 点赞 | 不接入 API | 跳转微博 App，用户手动操作 |

### 4.4 前置准备

1. [微博开放平台](https://open.weibo.com/) 注册开发者，创建应用，获取 App Key / App Secret
2. [微信公众平台](https://mp.weixin.qq.com/) 注册小程序，开通订阅消息
3. 部署后端服务（HTTPS 域名，用于 OAuth 回调）
4. 准备 1 个专用微博账号 Cookie（仅用于发博监测，与粉丝绑定账号分离）

## 六、接口清单（后端）

| 接口 | 方法 | 说明 |
|------|------|------|
| `/auth/wechat` | POST | 微信小程序 code 换 session |
| `/auth/weibo/url` | GET | 生成微博 OAuth 授权 URL |
| `/auth/weibo/callback` | GET | OAuth 回调，存 token |
| `/stars` | GET/POST/PUT/DELETE | 明星列表与管理（写操作需管理员） |
| `/admin/status` | GET | 监测与推送配置状态 |
| `/admin/monitor` | PATCH | 开启/关闭发博监测 |
| `/notify/config` | GET | 订阅模板与当前用户订阅状态 |
| `/feed/latest` | GET | 最新发博提醒列表 |
| `/weibo/{id}` | GET | 微博详情 |
| `/comments` | GET | 评论列表（分页 + 关键词） |
| `/comments/send` | POST | 代发评论 |
| `/templates` | CRUD | 评论模板 |
| `/notify/subscribe` | POST | 记录用户订阅消息授权 |

## 七、已知限制（小范围群可接受）

| 限制 | 影响 | 应对 |
|------|------|------|
| 发博通知有延迟 | 非秒级 | 轮询 3～5 分钟；群内说明即可 |
| 微博 token 约 30 天过期 | 需重新绑定 | 过期前提醒；我的页一键重绑 |
| 评论 API 有频控 | 连发可能失败 | 提示稍后再试；v2 做发送队列 |
| 无法小程序内点赞 | 需跳转微博 | 复制链接 + 打开微博 |
| 监测 Cookie 约 3 月过期 | 监测中断 | 管理员定期更新；失败时告警 |
| 微信订阅消息有次数限制 | 不能无限 push | 引导用户长期保持订阅 |

## 九、给 AI / 开发的协作说明

开发时请遵循：

1. **前端**：uni-app + Tailwind，界面简洁、夜间可用（粉丝常夜间使用）
2. **安全**：App Secret、微博 token 仅在后端；小程序不存敏感凭证
3. **范围**：严格按 v1 功能实现，点赞跳转不做 API 对接
4. **审美**：信息层级清晰，核心操作（发评论、打开微博）使用固定底栏

## 十一、本地启动

### 后端

> 需要 **Node.js >= 18**（推荐 `nvm use 22`）

```bash
cd server
cp .env.example .env
npm install
npm run dev
# 访问 http://localhost:3000/health
```

### 前端

```bash
cd frontend
cp .env.example .env
npm install
npm run dev:mp-weixin
# 用微信开发者工具打开 frontend/dist/dev/mp-weixin

# 或生产构建：
npm run build:mp-weixin
# 用微信开发者工具打开 frontend/dist/build/mp-weixin
```

**若登录报 `url not in domain list`：**

| 方式 | 能否用 127.0.0.1 | 说明 |
|------|------------------|------|
| 开发者工具 **模拟器** | ✅ | 详情→本地设置→勾选「不校验合法域名」后重新编译 |
| **真机调试** | ❌ 需局域网 IP | 用工具栏「真机调试」而非「预览」；同样勾选不校验合法域名 |
| 扫码 **预览** | ❌ 需 HTTPS 域名 | 真机强制校验域名，必须配置公众平台 request 合法域名 |

**真机调试（推荐，本地开发）：**

```bash
# 1. 查电脑局域网 IP（Mac 示例）
ipconfig getifaddr en0

# 2. frontend/.env
VITE_API_BASE_URL=http://192.168.x.x:3000

# 3. 重新编译，手机与电脑同一 WiFi
cd frontend && npm run build:mp-weixin:lan

# 或分步：npm run env:lan && npm run build:mp-weixin

# 4. 开发者工具点「真机调试」（不要点「预览」）
```

**扫码预览（需公网 HTTPS）：**

1. 用 cpolar / ngrok 等把 `3000` 端口映射为 `https://你的域名`
2. [微信公众平台](https://mp.weixin.qq.com/) → 开发管理 → 开发设置 → **服务器域名** → request 合法域名填入该域名
3. `frontend/.env` 中 `VITE_API_BASE_URL=https://你的域名`，重新编译后再预览

> 构建命令会自动把 `project.private.config.json` 复制到 dist；**扫码预览不受该文件影响**，必须走 HTTPS 域名或改用真机调试。

> 在 `frontend/src/manifest.json` 的 `mp-weixin.appid` 填入微信小程序 AppID（须与 `server/.env` 的 `WECHAT_APPID` 一致）；在 `server/.env` 填入微信/微博密钥及监测 Cookie。未配置微信密钥时，后端会使用 mock 登录便于本地调试。

**Phase 3 额外配置：**

| 变量 | 说明 |
|------|------|
| `WEIBO_MONITOR_COOKIE` 或 `WEIBO_MONITOR_ACCESS_TOKEN` | 发博监测数据源（专用微博账号） |
| `WECHAT_SUBSCRIBE_TEMPLATE_ID` | 微信公众平台申请的订阅消息模板 ID |
| `WECHAT_SUBSCRIBE_FIELD_*` | 模板字段名，须与公众平台模板一致 |
| `ADMIN_OPENIDS` | 管理员 openid 白名单（逗号分隔，留空则不限制） |

### 微博 OAuth 绑定（发评论 / 读评论必配）

1. 打开 [微博开放平台](https://open.weibo.com/) → 登录 → **管理中心** → **创建应用**（类型选「网页应用」或「移动应用」均可，需支持 OAuth2）
2. 创建后在应用详情页复制 **App Key**、**App Secret**
3. 在应用 **授权设置** 里添加 **回调地址**（必须与下面 `WEIBO_REDIRECT_URI` 完全一致）：
   - 电脑模拟器调试：`http://127.0.0.1:3000/auth/weibo/callback`
   - **真机调试**（你当前场景）：`http://192.168.x.x:3000/auth/weibo/callback`（换成 `npm run env:lan` 输出的 IP）
4. 编辑 `server/.env`：

```env
WEIBO_APP_KEY=你的AppKey
WEIBO_APP_SECRET=你的AppSecret
WEIBO_REDIRECT_URI=http://192.168.31.228:3000/auth/weibo/callback
WEIBO_SERVER_IP=你的公网IP
```

> `WEIBO_SERVER_IP`：发评论时微博 API 要求的 `rip` 参数，填你服务器的公网 IP；本地可先填电脑局域网 IP 试跑，上线后改为服务器公网 IP。

5. **重启后端**：`cd server && npm run dev`
6. 小程序「我的」→ **绑定微博账号**，在 web-view 里完成授权

> 真机绑定时，授权完成后微博会跳转到 `WEIBO_REDIRECT_URI`，手机必须能访问该地址，因此不能用 `localhost`，要用局域网 IP 或 HTTPS 域名。
